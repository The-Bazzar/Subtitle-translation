# 翻译与校对会话兼容契约

状态：v2.1.1；涉及 D3/D6/D7 的请求、会话与翻译身份，需要实现 PR 评审。

## 主翻译调用

- 单次项目翻译创建一个 ChatSession，跨批保留实际 user/assistant 历史；不同项目、不同运行不共享会话。
- 基础温度恢复 0.3，Provider request_kwargs 的覆盖规则不变。
- system 顺序为既有风格/简介/完整 glossary、检索规则（启用时）、JSON 通用规则、2.0.2 原样批协议，最后追加联合翻译/语义 split 协议。
- user 的 items 只包含 id、实际源文及 retrieved_context；RAG 按 TRANSLATE_BATCH_SIZE 分组调用 retrieve_texts(texts)，不覆盖 top_k，让 EMBEDDING_TOP_K 生效。
- 各批按 RAG -> LLM -> 检查点顺序执行，不预取全项目。后续检索失败不阻止之前成功批次保存，缓存验证仍在当前批检索后进行。
- 不再附加 context_before/context_after，删除 TRANSLATE_CONTEXT_WINDOW。联合 split 仍只占同一请求回合，不恢复独立 split 调用。
- 翻译最多三次尝试，重试间隔 3/6 秒；上下文超限直接停止，不重复发送超限请求。传输/JSON 失败恢复本轮请求前的历史，再次发送同一请求，不积累重复 user；已通过结构校验的真实响应正常保留。
- 保留实际非空译文、局部失败项重试、整句回退、检查点、日志和取消传播。source_review 保持原有两次尝试及独立会话，其他工具调用不变。

## 纯译文校对调用

- 创建独立于翻译的项目内共享 ChatSession，温度 0.2，跨批保留真实请求/响应；不同项目及运行隔离。
- 保留 2.1 的整句与 split_events 嵌套结构，同回合保存两级目标文本，不改源文、事件 ID/数量或时间；不恢复旧版源文纠错职责。
- PROOFREAD_BATCH_SIZE 按 event 数量计算预算，完整句为不可拆分提交单元；多个句段按顺序合批，单句可超过预算。不能为了严格满足旧版扁平批量而拆开整句/事件结果。
- RAG 使用 2.0.2 的逐 event Source/Target 检索 query 和配置 top_k，查询文字不扩大校对的目标语言职责；结果放入对应事件的 retrieved_context，不再附加独立邻句字段。完整 glossary 继续常驻 system。
- 各完整句批次检索后立即调用同一会话，不预取后续批次；超限缩批复用该批实际检索结果，不额外扩大工具调用。
- 最多三次尝试，3/6 秒退避；共享历史回滚规则同主翻译。上下文超限立即缩小句批次，单句再尝试移除动态 RAG，仍失败则保留原译文并警告，不截断 glossary、不拆分句段或回调上游。
- 缩批后仍使用同一真实会话，不自动裁剪已成功历史。完整对话本身超限时仍可能保留后续原译文，不宣称缩批必然解决全部超限。

## 显式 translate 重跑

普通 subtitle-translation translate 每次从原始 JSON/采用稿重建语义结果，重新请求翻译和联合断句；PROOFREAD=1 时重新校对。--only-scenes、--only-glossary 和 --only-output-path 保持独立操作，不触发全流程。

CLI 通过内部参数区分显式运行与 pipeline/batch 阶段调用；不增加 CLI 开关，不把 FORCE_REBUILD 全局打开。分别绕过 .beautified.json、MFA 文本检查点和最终定时投影的语义结果复用，并清空本次工作副本上的旧译文/事件/身份。MFA 后必须绕过旧定时投影，避免相同新译文触发加载旧校对结果。

原始 ASR 不改写。glossary/采用稿、检索库、场景与原生 MFA 声学缓存仍按既有规则复用；文本/窗口改变时按声学身份自然失效。成功后覆盖派生字幕，不要求用户删除项目文件。失败/取消不得导出空译文或把旧结果标为本次成功。

## 内部续跑缓存

semantic-bilingual-events-v2-shared-session 区分旧调用结果；prompt、模型、实际 RAG 输入、源文和 generation 继续绑定身份。
为验证实际输入，按批读取 RAG 也可能覆盖缓存项目；这保留 2.1 的严格缓存校验，不能退回仅凭 translation 非空就判定完成。
命中的句段只记录缓存结果，不请求模型、不重建虚假的历史。部分续跑只对待处理句段构建新会话，不恢复跨进程聊天，与 2.0.2 的待处理项语义一致。
pipeline/batch 与默认程序化阶段入口保留此策略；显式 translate 不复用保存的译文/校对结果。
完整历史随运行增长，不自动裁剪或总结；需要同时考虑供应端上下文和输出限制，不承诺消除长项目的上下文上限。
原生 MFA 仍按实际音频/定稿/corpus/工具身份复用，不因为翻译请求方式改变就重跑声学模型。

## v2.0.2 基线复审

| 范围 | 保留的基线行为 | 2.1 叠加边界 |
|---|---|---|
| LLM 客户端 | 模型解析、密钥/headers、request_kwargs、response_format 及 SDK 默认重试 | 仅 source_review 副本有专用超时/重试预算，不传染翻译或校对 |
| glossary/Tavily | 原始听录索引先建、RAG 传入既有工具/查询链、完整术语常驻 | glossary 后新增采用稿；启用 MFA 不跳过术语检索 |
| 翻译/校对 | 批次按 RAG -> LLM 顺序处理、共享真实会话、原有温度/退避 | 联合双语 split、源文/事件身份只读保护与新结构 |
| 响应文本 | ISO 语言键大小写规范化、最多三层 EN/ZH/SRC/TGT 标签清理 | 只清理目标，不改冻结源文；清理后非空保护，校对重复目标键拒绝 |
| 元数据 | 同次翻译标题/简介/标签/原片章节、完整 glossary、失败回退 | 仅日志适配，不改工具/模型调用 |
| 媒体/batch | 下载 cookies/清缓存、编码与 ASR 资源、generation/锁/原子发布 | MFA postprocess、环境配置入口和统一日志 |

修复 MFA glossary 遗漏检索器、全项预检索和回复标签清理缺失；不恢复已经删除的独立 split、时间美化/吸附、源文校对或旧 CLI 开关。
旧版对错误类型或空译文的宽松接受不恢复：完整译文缺失仍有界重试/失败，分割结构失败但整句有效则保留整句；pending 时间不能导出。上述限制与纯译文/嵌套结构契约优先，不能用原样复制旧解析器替代。
旧 batch 删除项原本已因失效 subprocess/marker/terminal 路径标记跳过，不恢复这些失效测试；当前资源、取消、generation/锁/发布测试继续执行。

## 验证

mock SDK 验证第二批确实包含第一批 user/assistant；验证项目隔离、温度、批量 RAG 默认值、完整 glossary、重试历史及 3/6 秒退避。
校对覆盖 event 预算、完整句原子接受、逐 event RAG、超限缩批/去 RAG、失败保留原译文和源文/时间只读。
CLI 连续运行两次验证翻译与校对均调用两次；MFA 路径同时绕过文本及定时投影，不强制重建采用稿。only 模式和内部入口不触发显式重跑。
同一模拟输入分别执行 v2.0.2 与当前实现，对照工具顺序、RAG 文本/参数、SDK 非 messages 参数和会话角色序列；差异限定在新增响应协议及已定义的新结构。回归测试固定逐批顺序、后续检索故障、MFA glossary 检索器和目标标签清理。
不更改外部维护的 prompt example，也不改源文审阅、MFA 声学执行、元数据和 batch generation/资源协议。
