# v2.1.0 ASR Provider Abstraction

Status: proposed

## Summary

v2.1.0 的候选主线是将现有 WhisperX-only 识别层抽象为可替换的 ASR provider，同时保持当前 JSON-first 下游完全兼容。

候选 provider：

- WhisperX：默认 provider、兼容基线和 fallback。
- Parakeet：优先验证英语识别质量、词时间戳和运行效率。
- Canary：优先验证法语、西班牙语等多语言能力。
- Future providers：通过同一 contract 接入，不向 pipeline 暴露厂商格式。

本设计不预先认定候选模型优于 WhisperX。是否进入默认路由必须由项目基准测试决定。

## Goals

- 将 standalone pipeline 与 batch worker 的 ASR 实现从 WhisperX 细节中解耦。
- 所有 provider 输出统一的 normalized ASR JSON。
- 保持 word timestamps 作为 split 对轴的唯一时间事实来源。
- 保留 WhisperX 作为默认值、fallback 和质量对照。
- 支持 metadata-only 的 ASR 前上下文，并按 provider capability 转换为 hotwords 或 prompt。
- 为英语 Parakeet 与多语言 Canary 建立可重复 A/B 基准。
- 为后续 ASR disagreement 检测和检索辅助仲裁预留 sidecar contract。

## Non-goals

- v2.1.0 不删除 WhisperX。
- 不改变 `beautify -> glossary -> translate -> split -> proofread -> ASS` 的顺序。
- 不让 LLM 或网页搜索直接改写 `words[]`、word 时间戳或原始 `text`。
- 不默认启用 ensemble；它是通过单 provider 路径验证后的扩展能力。
- 不把 NVIDIA NeMo 等重量依赖强制安装给只使用 WhisperX 的用户。

## Current Integration Points

当前有两条 ASR 路径：

1. Standalone：`subtitle_translation.stages.transcribe_video()` 直接调用 WhisperX executable。
2. Batch：`AsrWorkerController` 管理 `_WhisperXBackend`，执行 `LOAD_ASR -> TRANSCRIBE -> UNLOAD_ASR -> LOAD_ALIGN -> ALIGN`。

provider abstraction 必须同时覆盖两条路径。不能只新增一个 standalone `asr.py` 而让 batch 保持 WhisperX-only。

## Normalized Data Contract

最终供 `translate_srt.py` 使用的 JSON 继续保持：

```json
{
  "language": "en",
  "segments": [
    {
      "id": 1,
      "start": 12.34,
      "end": 15.67,
      "text": "example",
      "words": [
        {
          "word": "example",
          "start": 12.34,
          "end": 12.80,
          "score": 0.97
        }
      ]
    }
  ],
  "_asr": {
    "schema_version": 1,
    "provider": "whisperx",
    "model": "large-v3-turbo"
  }
}
```

Required invariants：

- `language` 必须规范为有效 ISO 639 主语言代码。
- segment 必须有有限、单调且非负的 `start/end/text/words`。
- 每个有效 word 必须有非空 `word`，成对的 `start/end` 必须有限且位于 segment 合理范围。
- normalization 只能修正厂商字段形状，不能静默改写识别内容。
- provider provenance 存入 `_asr`，但下游不得依赖某个具体 provider。

## Provider Contract

建议在 `core/subtitle_translation/asr/` 建立：

```text
asr/
├── types.py
├── provider.py
├── normalize.py
├── router.py
└── backends/
    ├── whisperx.py
    ├── parakeet.py
    └── canary.py
```

provider 需要声明 capability：

- `languages`
- `detects_language`
- `provides_word_timestamps`
- `requires_alignment`
- `accepts_hotwords`
- `accepts_prompt`

逻辑结果分两层：

1. `RecognitionResult`：provider 原始识别的 typed representation，word timestamps 可选。
2. `NormalizedTranscript`：满足项目必需 schema，word timestamps 必须可供下游使用。

若 provider 不提供可靠 word timestamps，必须进入明确的 alignment adapter；无法对齐时 provider 路径失败并按配置 fallback，禁止生成伪造时间码。

## CLI and Configuration

新增正式子命令：

```text
subtitle-translation asr VIDEO
```

`whisper` 子命令在迁移期保留为 WhisperX compatibility alias。

配置草案：

```text
ASR_PROVIDER=whisperx
ASR_MODEL=large-v3-turbo
ASR_FALLBACK_PROVIDER=whisperx
```

`ASR_PROVIDER=auto` 只有在路由基准和语言探测策略验证后才能开放。现有 `WHISPER_MODEL`、`WHISPER_ALIGN_MODEL`、`WHISPER_DEVICE` 在迁移期继续可读；显式新变量优先。

ASR cache fingerprint 必须新增 provider、model、provider options、normalizer schema version 和 context generation。不同 provider 的 cache 不能互相命中。

## Contextualization Before ASR

新增 `<base>.asr_context.json` sidecar。它只从 ASR 前可获得的信息构建：

- title
- description
- tags
- channel/uploader
- upload date
- 有界的网页证据

sidecar 可以包含：

- people
- places
- works/titles
- products/brands
- technical terms
- source URLs 与证据摘要

约束：

- context 只能作为 provider hotwords/prompt 或后续 evidence。
- 不得用 context 直接修改 raw transcript 或 `words[]`。
- provider 不支持 contextualization 时必须安全忽略，而不是把词表拼进普通音频文本。
- context 搜索需有独立预算和 cache，不复用完整 glossary 生成流程。
- context 内容或 generation 改变时，相关 ASR fingerprint 必须失效。

## Corrections and Timestamp Preservation

原始 segment `text` 与 `words[]` 保留 ASR 事实。检索或 LLM 确认的纠错通过现有 `proofread_text` 最终落盘；在 proofreading 前的候选纠错与争议项写入独立 sidecar，不提前覆盖 `proofread_text`。

建议 sidecar：

```text
<base>.asr_disagreements.json
```

它记录 provider 输出差异、疑似实体、证据与置信度，只作为 glossary/proofread 输入。这样既能修正显示文本，又不会破坏 split 对 `words[]` 的首尾匹配。

## Routing

初始行为：

```text
explicit provider -> capability check -> transcribe/align -> normalize
                                      -> failure -> configured fallback
```

`auto` 路由候选：

```text
language probe
├── English -> Parakeet candidate
├── supported multilingual -> Canary candidate
└── unsupported/uncertain -> WhisperX
```

语言 probe 不能只信任 YouTube metadata。v2.1.0 必须比较短音频 probe、provider 自带 language detection 与 metadata hint，确定可靠策略后才启用 auto。

## Benchmark Gate

建立固定英语、法语、西班牙语样本集，至少评估：

- WER/CER
- 人名、作品名、品牌和技术术语错误率
- word timestamp coverage
- 时间单调性与 segment/word 边界合法率
- 下游 split alignment 成功率与 fallback 率
- real-time factor
- 峰值 VRAM/RAM
- 模型加载与多任务复用成本

provider 只有在 word timestamp 和下游 split 指标不退化时，才可能进入 auto routing。仅 transcription 文本更好不足以成为默认值。

## Delivery Phases

### Phase 1: Contract First

- 引入 typed provider/capability/result contract。
- 把现有 WhisperX 适配到 contract。
- 保持默认输出、batch cache 和下游结果不变。
- `whisper` compatibility alias 继续通过。

### Phase 2: Parakeet English A/B

- 作为 opt-in extra 安装。
- 验证英语 word timestamps、模型常驻和 batch worker 生命周期。
- 输出与 WhisperX 的离线对比报告，不改变默认 provider。

### Phase 3: Canary Multilingual A/B

- 作为 opt-in extra 安装。
- 重点测试法语、西班牙语及混合语言。
- 无可靠 word timestamps 时接 alignment adapter 或判定不可用。

### Phase 4: Routing and Fallback

- 实现 capability gate、language probe 和 deterministic fallback。
- 开放 `ASR_PROVIDER=auto` 前必须通过 benchmark gate。
- 文档化下载体积、显存和硬件限制。

### Phase 5: Disagreement Retrieval (Stretch)

- 对相同片段的 provider 输出做 token/entity diff。
- 只将争议实体交给现有 Tavily/web evidence/RAG 路径。
- 仲裁结果进入 sidecar 和 proofreading evidence，不改 raw timestamps。

若 Phase 5 影响 v2.1.0 稳定性，应顺延到 v2.2.0，不阻塞 provider abstraction 发布。

## Compatibility and Migration

- 默认 `ASR_PROVIDER=whisperx`，升级后行为不变。
- 现有最终 WhisperX JSON 继续可读。
- 旧 ASR recovery sidecar 若缺少 provider/normalizer fingerprint，明确视为 cache miss。
- 新 provider 依赖通过 optional extras 安装，setup 只按用户配置同步所需 backend。
- `translate_srt.py` 不解析厂商结果，只接收 normalized transcript。

## Acceptance Criteria

- standalone 与 batch 使用同一 provider registry 和 normalizer。
- WhisperX 默认路径通过现有完整测试且产物兼容。
- 每个 provider 有 schema、capability、fallback、cache isolation 回归测试。
- 任何成功输出都具有可验证 word timestamps。
- provider crash 保持现有 worker fail-fast、日志和恢复语义。
- 关闭 contextualization 时不产生网络请求。
- LLM/web evidence 永不直接改写 raw `text` 或 `words[]`。

## Open Decisions

- Parakeet/Canary 具体模型版本及许可证。
- provider 是否能原生输出满足项目要求的 word timestamps。
- language probe 的模型、采样长度和置信阈值。
- NeMo/PyTorch 依赖与现有 torch backend 的隔离方式。
- context sidecar 搜索预算和失效策略。
- Phase 5 是否留在 v2.1.0。
