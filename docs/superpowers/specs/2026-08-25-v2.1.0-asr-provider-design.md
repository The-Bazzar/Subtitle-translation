# ASR 兼容层、glossary 原文校对与 MFA 对齐研发路线图

状态：本轮目标设计，尚未实现；2026-11-09 修订。首版 en -> zh，保留多语言入口。

[完整设计](2026-11-07-en-zh-multi-asr-design.md)是目标行为主文档；本文只维护范围和交付顺序，[Provider 输出考据](2026-11-07-asr-provider-output-contracts.md)维护固定源码及格式证据。当前运行行为仍以 AGENTS.md 和代码为准。

## 1. 当前目标流程

```text
download -> prepare-video -> 纯 ASR 识别 / 候选 bundle
  -> glossary：术语整理 + 文本优选与字幕编辑
  -> MFA：完整修订稿统一对齐
  -> beautify -> 独立 LLM 源文断句 -> 本地校验/对轴，预填 split_events.en
  -> translate：单回合整句翻译 + 译文分配，填充 split_events.zh
  -> 可选纯译文 proofreading -> ASS -> burn
```

正式逐词 beautify 位于 MFA 之后。MFA 前移除 ASR LLM 纠错，MFA 后不再自动修改源文，不形成校对返工回路。

保留独立 LLM split 阶段，移到 MFA/beautify 后、translate 前且只处理源文；本地仅校验边界并映射时间，不替代 LLM 语义断句。不把 MFA/VAD 分段直接作为语义字幕边界，MFA 只负责时间定位。

## 2. 引擎与安装

- setup 默认预选 WhisperX，可替换为单一 Parakeet、Qwen-ASR 或已支持的其他引擎，也可增设多个来源。
- 只安装、准备和调用选中的引擎，安装集合与启用集合分别记录；未选依赖不得 eager import。
- 单来源直接提供实际听录，多来源保留所有有效候选；无论数量多少，ASR 均不调用语义 LLM。
- WhisperX 的默认安装地位不赋予其正确答案、分段或词轴权威。
- MFA 是基础对齐工具，但执行位置为 glossary 修订之后，不属于识别器内部。
- 依赖和平台支持按实际 backend profile 验收，不能把源码考据当作已运行兼容。

Parakeet/NeMo 的 Hypothesis 与 Qwen SDK 的 ASRTranscription 转换规则参见输出契约。统一 SourceResult v1 不要求原生词轴；正式 AlignedTranscript v2 只使用 MFA 结果。

## 3. 阶段和数据契约

### ASR

现有 standalone 和 batch 两条识别路径统一到共享 adapter/worker 协议。输出 CandidateBundle、不可变 SourceResult、实际兜底稿和音频范围。原生分段只作证据，不作为全流程硬边界。

ASR 不读写 glossary、不注入术语知识、不进行 LLM 语义优选。已有 model/设备兼容变量只影响显式选中的相应引擎。

### Glossary 与 source review

这是唯一自动源文编辑阶段，使用候选、语义、术语和上下文统一优选文本、编辑字幕。既处理多源差异，也允许单源的人名、近音词和语境校对。允许忠实原意的最小语法修改，保留玩梗和有表达作用的非标准措辞；意图不明时优先保留。不能在 split、translate 或 proofreading 再做一次原文纠错。

输出 glossary.md 和 source_review.json，以 generation manifest 关联。每个源文项有实际非空 text 和修改依据；坏响应、超时、无法确定或缺项时输出提前准备的实际 fallback，不返回空文或仅疑点标签。

glossary 不负责最终字幕断句。采用稿不等于已证明的实际发音；候选一致、语义通顺或 MFA 对齐成功均不证明听录正确。不设置自动音频复核，保存不可变候选、最终采用稿及修改记录，不另建声称真实的权威稿。

非空 glossary.md 不等于本次源文已校对；源文缓存还要匹配输入与 source_review 身份。显式 skip knowledge 跳过术语和纠错，实际稿 passthrough 后继续 MFA。only-glossary 只输出两份语义产物，不进入对齐和翻译。

### MFA 与正式输入

完整 source_review 修订稿都进入 MFA，包括未匹配任何完整 ASR 候选的文字。长音频实际按独立音频/文本块运行，再恢复全局词轴；不让 Provider 错误边界限制后续句段。

MFA 失败时保留实际修订稿和粗时间，words 为空并标记原因及最终人工定时/断句，不能回退旧文稿、切换对齐器或伪造时间。

AlignedTranscript v2 的 text 与 words 绑定 source_review 文字版本；精确字段和示例以完整设计为准，不在路线图维护另一份 schema。

### 源文事件规划、翻译与 proofreading

MFA 和 beautify 后，独立 LLM 源文断句结合完整语义、词轴/停顿和字幕约束，只返回合法边界 ID，不改文字或生成时间。本地验证覆盖、顺序和不可拆范围，映射词轴，生成事件 ID、源文和时间，并预填 split_events.en。失败有界重试后整段降级，不用本地句界库替代语义断句；无有效词轴内容不发断句请求，保留完整源文及粗时间，整段翻译后交人工。

translate 每项输入完整句段和其全部 split_events.en，结合相邻上下文/常驻 glossary，在同一请求/响应中先生成整句译文，再拆分填入固定 ID 的 split_events.zh。不能孤立逐条翻译，也不另请求译文断句；不得清空已有规划或改事件数量/源文/时间。

同一响应返回整句译文及全部事件译文，按语言拼接规则必须可完整还原。缺项、重复/未知 ID、空译文或拼接不一致时，以完整句段为单位有界重试和原子提交，不混用不同响应。无完整有效产物则明确失败，不把英文或空串当中文导出。校对若更新事件译文，也同步整句字段。

译后检查源/目标行长、显示时长、阅读速度和内容完整性；过长或表达不自然交人工，不截断、强切或回调 split。en/zh 为历史字段名，多语言接口按实际语言代码序列化。proofreading 若启用，只改译文，不改源文、event 数量或时间，也不回调前序阶段。

源文和译文疑点写非展示记录，最终人工处理；正文不加存疑问号、括号注释或待确认标签。正常内容标点保留。校对失败保留实际原译文，正常导出。

是否移除 proofreading 通过译文质量、人工修订量、成本和耗时对照评估；目前仅收缩职责并保留既有跳过开关，不宣称功能已经删除。

## 4. 缓存和资源

- ASR 候选身份只绑定音频、Provider/backend、模型、依赖、输入范围和识别参数，不绑定 glossary。
- glossary/source_review 身份包含候选、实际输入稿、术语及证据快照、模型/prompt、fallback 规则和 schema。
- MFA 身份绑定实际修订文字及对齐资源。术语变更需要重做语义检查，但实际文字不变时可复用相同 MFA。
- 源文 split 模型/prompt、约束或边界变化但文字不变时复用 MFA，重新校验规划，使不匹配的完整句段译文失效；规划依赖文字、上下文、词轴和策略，不依赖译文。
- 翻译缓存绑定事件规划身份、上下文、术语、模型/prompt 和拼接策略；整句及全部事件译文原子匹配，提前填英文不表示完成，旧整段 translation 不自动分配到新事件。
- 正式 JSON 需同时绑定 source_review 和 MFA 身份，不能混用半份更新或旧词轴。
- 识别模型波次、CPU/IO 预算、NVENC 互斥、MFA jobs、取消和原子发布仍由统一调度层管理。
- batch 阶段依赖拆为 recognize -> glossary/source_review -> MFA -> remaining postprocess；远程语义等待不保留已经完成的 GPU 模型。
- 现有锁、generation 和 candidate 提交边界继续适配，不把旧 .asr.json 重新解释成厂商裸输出。

## 5. 交付顺序

1. 定义 CandidateBundle、SourceResult、glossary/source_review 双输出、AlignedTranscript、独立 LLM 源文断句及单回合整句/事件翻译契约，更新共享配置和缓存身份。
2. 跑通默认单源识别 -> glossary 文本优选/编辑 -> MFA -> beautify -> 独立 LLM 源文断句及本地事件规划 -> translate 单回合整句翻译/事件分配 -> 后续字幕链路。
3. setup 支持可选引擎替换和扩充，分别采集真实输出 fixture，验证单一 Parakeet/Qwen。
4. glossary 接入多源候选、语境和实际 fallback，移除 ASR 语义调用。
5. 移除 translate/proofread 的源文修改和历史缓存覆盖，保留纯译文校对及 skip。
6. 适配 batch、取消、资源预算、源文/术语 generation、MFA 部分失败与人工报告。
7. 对照旧整句翻译后双语 split 与新源文断句后单回合整句翻译/事件分配，报告双语自然度、超长/过快字幕比例、人工重切量及请求/token/耗时；另做纯译文校对收益对照，再决定是否删除 proofreading。

## 6. 验收与迁移

必须测试 ASR 无语义 LLM、单源也可进入 glossary 校对、候选一致不直接跳过语义校对、glossary 双缓存、坏响应实际 fallback、MFA 只对实际采用稿运行、文字不变时复用 MFA、后置源文只读和正常字幕输出。

新增独立源文断句的阶段顺序、原文覆盖/只读、坏边界整段降级、无轴不强切、翻译保留预填事件、单回合整句翻译及事件分配、响应 ID/拼接校验、整句原子重试/提交、边界变化仅失效下游缓存测试；正常路径不得额外调用译文 split，失败重试独立计数。

preflight、模型异常和 worker 崩溃仍分开处理。所有单元测试 mock 外部模型/工具，真实安装、推理、MFA 和人工基准另行验收。Provider 格式考据仍只代表固定源码核对。

asr 的新输出为候选 bundle；translate 需接受 bundle 或旧 JSON 并继续 glossary/MFA。入口语义、旧 skip、only-glossary、split 源文边界协议、translate 单回合整句/事件响应、工作缓存和导出字段的迁移须在实现时明确；不能把无词轴候选冒充已对齐的正式字幕输入。split 配置继续用于前置源文断句，但旧双语请求/缓存不复用；旧 split_events 缺少规划身份时重新断句并重译，保留 split SRT 检查输出文件名。

本轮作为正常迭代，D1/D2/D3/D4/D6/D7/D10 涉及的数据源、顺序、缓存、LLM、split、职责与安装差异在实现 PR 中说明，同步技术文档、MIGRATION、examples 和两套 setup；正式 prompt 在既定仓库维护。
