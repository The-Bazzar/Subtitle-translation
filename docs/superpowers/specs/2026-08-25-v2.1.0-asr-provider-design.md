# ASR 兼容层、多源勘误与 MFA 对齐研发路线图

状态：当前研发路线图，功能尚未实现。首阶段验证 `en -> zh`，保留多语言扩展接口。

本文定义本轮迭代的范围、顺序与完成条件。[英文多 ASR 勘误与词级对齐设计](2026-11-07-en-zh-multi-asr-design.md)定义阶段契约、数据流、失败处理及待定细节。两份文档描述同一方案，不能按旧版本的可选功能或延期安排解释本轮交付；当前运行行为仍以 `AGENTS.md` 和代码为准。

## Summary

本轮迭代将现有 WhisperX-only 识别层扩展为可选择的 ASR Provider、单来源透传、可选多源原文勘误和 MFA 统一对齐，继续采用 JSON-first 输入。Setup 默认预选 WhisperX，用户可增设或替换为其他已支持引擎，单来源不限于 WhisperX。多源能力、非空文本 fallback、MFA 和下游适配均为当前研发内容，但不要求用户默认安装或同时启用多个引擎。

```text
setup 选择的 ASR -> 单来源实际文本 passthrough
                -> 多来源比较 -> 有分歧时 LLM 勘误 / 实际文本 fallback
  -> 完整最终稿 -> MFA 分块批量对齐 -> 统一 JSON
  -> beautify -> glossary -> translate -> split -> proofread -> ASS
```

候选 provider：

- WhisperX：setup 默认预选项，在多源比较中仍是普通 Provider。
- Parakeet：验证英语候选听录及运行效率，原生词轴仅用于候选映射和诊断。
- Qwen-ASR：通过同一接口提供候选文字，不要求自带最终词轴。
- Future providers：通过同一 contract 接入，不向 pipeline 暴露厂商格式。

所有 Provider 处于平等关系，不预先认定 WhisperX 或其他模型的结果正确。单引擎结果和多源勘误结果均使用独立人工标注评估；模型是否参与识别由能力与配置决定，不能把某模型设为内容裁决标准。

用户可以只选择 Parakeet、Qwen-ASR 或其他已支持的单一 Provider，不需要保留 WhisperX。单来源模式由来源数量决定，不按模型名称分支；直接透传实际文字，跳过 ASR 勘误 LLM，再进入 MFA。

## Goals

- 将 standalone pipeline 与 batch worker 的 ASR 实现从 WhisperX 细节中解耦。
- 将各 provider 原始结果转换为共享候选表示，保留各自来源和原始文字。
- 单来源 passthrough、多源勘误与 fallback 均为每个句段提供非空实际文本，并汇总完整最终稿。
- MFA 为完整最终稿提供正式词轴，split 仅使用通过校验的 MFA 结果。
- 保留 WhisperX 适配器及兼容入口，取消其在多源主流程中的默认裁决和专属 fallback 地位。
- 以前置多源候选及同一音频的相邻听录文本处理漏听和明显语素错误，不依赖 glossary；来源匹配仅供追溯，不限制 MFA 对齐资格。
- 无可用词轴的部分保留实际文本和粗时间，跳过自动 split，流转到最终人工定时及断句。
- 以固定英文人工听录及词轴标注验证各单引擎、多源勘误和 MFA 的整体效果。
- 翻译和 proofreading 在 `translate_srt` 内使用 glossary 及语境，按需校对人名、近音名词等源文疑点，并重点保证译文正常输出；不返工 ASR 或 MFA。

## Non-goals

- 保留 WhisperX 适配器和显式单引擎兼容入口，不赋予其在多源流程中的内容权威。
- 不改变 `beautify -> glossary -> translate -> split -> proofread -> ASS` 的顺序。
- 不让 LLM 或网页搜索直接改写 `words[]`、word 时间戳或原始 `text`。
- 本轮不验收其他源语言、语言混说、自动选模、流式识别、音频 LLM 复核或联网纠错；保留扩展接口。
- 不把 NVIDIA NeMo 等重量依赖强制安装给只使用 WhisperX 的用户。

本轮实现默认单来源及用户可选的多来源两条路径。安装和运行成本按用户所选引擎承担；多源能力需要相应回归，但不是每个用户的使用前置条件。

## Current Integration Points

当前有两条 ASR 路径：

1. Standalone：`subtitle_translation.stages.transcribe_video()` 直接调用 WhisperX executable。
2. Batch：`AsrWorkerController` 管理 `_WhisperXBackend`，执行 `LOAD_ASR -> TRANSCRIBE -> UNLOAD_ASR -> LOAD_ALIGN -> ALIGN`。

provider abstraction 必须同时覆盖两条路径。不能只新增一个 standalone `asr.py` 而让 batch 保持 WhisperX-only。

## Normalized Data Contract

正式字段以 [完整设计第 8 节](2026-11-07-en-zh-multi-asr-design.md#8-正式-json-与工作源文)为准，不在路线图复制独立 schema。

- SourceResult v1 表示原生候选、来源与输入范围，不要求精确原生句段或词轴。
- ASR Transcript v2 是 passthrough / 勘误后经 MFA 处理发布的正式 JSON，保留 language、segments、text、words 和句段时间。
- MFA 失败时 words 为空，必须显式记录词轴不可用、粗时间来源和人工处理状态，不能撤销实际源文。
- 原始 Provider 分段、MFA 处理块、翻译句段与字幕 event 分开，不能复用为不可跨越边界。
- translate_srt 的后置源文修订保存在工作副本，不反向覆盖 ASR JSON 和 MFA 词轴。

## Provider Contract

字段级依据见 [ASR Provider 原生输出考据与适配契约](2026-11-07-asr-provider-output-contracts.md)。本次已核对 Parakeet/NeMo 的 Hypothesis、时间戳转换及 Qwen 官方 wrapper 的 ASRTranscription；两者真实转录和目标平台运行仍待验证。

模块划分和目录以完整设计第 4 节为准，路线图不再维护另一套模块名称。

provider 需要声明 capability：

- `languages`
- `detects_language`
- `provides_word_timestamps`
- 原生词轴仅作为候选映射及诊断能力，正式对齐语言和模型由独立 MFA adapter 声明。
- `accepts_hotwords`
- `accepts_prompt`

逻辑结果分两层：

1. `SourceResult v1`：Provider 候选文字、来源和输入范围，原生分段及词轴可选。
2. `ASR Transcript v2`：满足正式输入 schema；自动 split 的句段需要可用词轴，MFA 对齐结果不可用的部分按补充提案显式标记原因并交由人工断句。来源未精确匹配候选本身不是词轴不可用的原因。

详细设计确定正式词轴统一由 MFA 生成。ASR Provider 提供候选文字和来源，调用方记录输入音频覆盖范围；不要求 Provider 一定输出原生句段或词轴，不伪造模型未提供的时间。原生对象先转为共享 Source Result，再由勘误 / passthrough 和 MFA 生成正式输入。MFA 结果须经过文字映射及时间合法性校验，失败时保留勘误稿并交由人工处理。

## CLI and Configuration

新增正式子命令：

```text
subtitle-translation asr VIDEO
```

`whisper` 子命令在迁移期保留为 WhisperX compatibility alias。

首版使用本地 asr_providers.json 表达 enabled 集合、各引擎模型、勘误 LLM 和 MFA 资源，asr_runtime.json 记录工具路径及安装版本。字段、解析优先级和 CLI 迁移以完整设计第 3、13 节为准；不再使用全局单一 Provider 加固定 WhisperX fallback 表达多源流程。

Setup 提供模型集合选择，默认预选 WhisperX，允许替换为单一 Parakeet 等引擎；只安装所选依赖和准备所选资源。已安装集合与实际启用集合分别记录，未选择的适配器不得通过 eager import 强制引入依赖。两套 setup 行为一致，升级保留已有选择。MFA 是所有识别组合共有的基础对齐依赖。

`whisper` 显式单引擎入口及旧 WhisperX 变量的兼容迁移需要单独处理，不能由兼容变量推导出 WhisperX 是多源模式的必需来源或正确答案。语言自动路由属于后续能力，不在首阶段英语验证中开放。

ASR cache fingerprint 必须包含 provider、model、provider options、normalizer schema version 及实际使用的听录上下文身份。不同 provider 的 cache 不能互相命中；glossary 不属于前置 ASR 输入，其变化不使 ASR 或 MFA 缓存失效。MFA 发音词典属于独立对齐资源，仍纳入对齐身份。

## ASR and Glossary Boundaries

进入 `translate_srt` 前的多引擎识别、LLM 优选勘误及 MFA 均属于 ASR 阶段，处理漏听、明显语素听录错误、重复或缺词、句段对应及时间轴漂移。它们只使用实际候选、同一音频的相邻听录上下文及识别 / 对齐资源，不生成、读取或依赖 glossary，不调用术语检索或网页证据，也不把 glossary 转成 ASR hotwords/prompt。

MFA 的声学模型、发音词典及词典外词发音处理用于对齐，与项目的术语知识库分开。为原文准备发音不能变成基于术语库改写听录文字。

ASR 正式文稿进入 `translate_srt` 后，继续执行既有的 beautify、glossary、翻译、断句和校对。翻译或 proofreading 对人名、读音相近的名词、词语不符合语境等有疑议时，才结合 glossary、上下文和已取得的证据对源文作有依据的局部校对；无法可靠确定的部分保留实际文本，留给最终人工。

后置源文校对保存在翻译工作副本及校对字段，不反向覆盖 ASR 文稿或 MFA 词轴，不回调上游。Glossary 仅影响后续翻译和校对流程，不能成为本轮前置 ASR 的依赖，因而不存在首次运行时等待下游 glossary 才能勘误的循环。

## Corrections and Timestamp Preservation

ASR 文稿受模型能力限制，前置听录勘误必须比较多个可追溯来源，在翻译前形成实际源文，不依赖 glossary。阶段详细规则见 [英文多 ASR 勘误与词级对齐设计](2026-11-07-en-zh-multi-asr-design.md)。翻译和 proofreading 的边界限定在 `translate_srt` 内，允许对术语和语境类源文疑点作局部校对；不返工 ASR 或 MFA。无法可靠解决的疑点留给最终人工，当前代码行为尚未因此改变。

需要分别定义原始候选和最终稿：各 ASR 的原始 `text`、`words[]` 与来源记录保持不可变；显式单来源直接 passthrough，多来源有分歧时才进行 LLM 勘误，经 MFA 对齐及规范化后供下游使用。每个句段始终提供实际文字；LLM 失败时使用提前准备的非空 `fallback_text`，不能只保留争议标签或候选列表。正常单来源透传、来源异常造成的降级透传和 LLM fallback 分别记录，均不赋予 WhisperX 特权。

词轴用于 split 阶段的自动断句与对轴。多源勘误后的完整最终稿交给 MFA 统一对齐，包括未匹配任何完整 Source Result 的段落。候选匹配仅用于来源追溯，不限制对齐资格。MFA 结果不可采纳或分块边界不可靠时保留最终文字和可用粗时间范围，跳过受影响部分的自动 split，流转到最终人工定时和断句，不要求自动阶段保证粗边界准确。

MFA 使用已采纳文字、对应音频、声学模型与发音词典，不产生新的勘误来源。对齐失败或校验失败时保留勘误稿并转人工断句，不改走其他对齐方案。逻辑上输入完整最终稿，长音频实际执行时需要独立于原 ASR 分段的音频 / 文本处理块，并在对齐后恢复全局词轴；不能把 ASR 的错误断点带入最终句段。词轴不可用状态必须在 beautify、split、缓存恢复和导出中被识别。

对齐失败不得回归勘误前原文，也不得选择其他候选替换勘误稿；仅将受影响部分标记为词轴不可用和待人工断句，翻译及译文校对继续使用勘误稿。

候选差异、采纳记录、词映射及回退原因保存在独立 sidecar。前置 ASR 正式文字变化时重新判定 MFA 及下游缓存；后置术语或语境校对只更新 `translate_srt` 内的工作源文和对应译文，不反向覆盖 ASR 输入或重跑 MFA。Split 前源文改词导致词轴不再对应时跳过自动 split，split 后局部修订保留既有 event 边界；不把新文字写入旧词轴。未解决的疑点写非展示记录供最终人工处理，不能向译文正文追加存疑问号、括号说明或待确认标签。

## Routing

多源主流程：

```text
configured provider set -> capability check -> recognize candidates
  -> one source: passthrough -> MFA -> normalize -> downstream
  -> multiple sources: compare -> reconcile / passthrough -> MFA -> normalize -> downstream
```

WhisperX 业务结果不可用不触发专属失败分支：若其他有效候选满足多源条件，可继续勘误和 MFA。勘误阶段已有明确 fallback，正常结果和 fallback 都提供非空文字进入后续流程，但来源不足或无法裁决不能被标为多源勘误成功。底层 worker 崩溃仍按统一的 fail-fast 及资源回收语义处理，不区分模型身份。

单来源路径不初始化 ASR 勘误 LLM，不要求该 LLM 的模型或 API key，实际文字必须继续 MFA；该规则同样适用于只选择 Parakeet 等来源的用户。显式启用多个来源但只剩单份有效结果时另记降级，不把用户主动选择的单来源当作错误。

未来多语言路由决定参与识别的候选集合，而非固定回退到 WhisperX。语言 probe 不能只信任 metadata，具体策略需经独立验证。

## Benchmark Gate

本轮建立固定英文人工听录和词轴标注集，以 `en -> zh` 流程验收，至少评估：

- WER/CER
- 人名、作品名、品牌和技术术语错误率
- 勘误修正率、新增错误率、fallback 使用率及来源不足情况
- word timestamp coverage
- 时间单调性与 segment/word 边界合法率
- 下游 split alignment 成功率与 fallback 率
- 全部句段的自动完成率、待人工定时及断句的数量和时长占比
- real-time factor
- 峰值 VRAM/RAM
- 模型加载与多任务复用成本

分别评估 Provider 候选文字质量、多源勘误收益、MFA 时间轴和下游翻译输出，不因某个 Provider 缺少原生词轴而排除其候选资格。自动 split 指标需同时报告人工处理工作量，不能通过排除失败句段虚增结果。其他语言基准及自动路由属于后续扩展。

## Delivery Phases

### Phase 1: Shared Contracts and Data States

- 定义共享候选、来源、句段映射、实际文本 fallback、词轴可用性和人工处理状态。
- 区分不可变原始候选、勘误稿、MFA 结果及正式 JSON。
- 保留语言参数、语言策略和能力检查接口，当前只验证 `en -> zh`。
- 明确旧 JSON 读取兼容和新 schema/cache 失效策略；保留恢复协调的锁与原子发布边界。

### Phase 2: Setup and Optional ASR Providers

- 先跑通单 Provider 通用链路，setup 默认预选 WhisperX，并支持用户改选其他已支持引擎。
- 依据官方源码固定每个 backend 的输出 profile，采集真实结果作为 fixture；不能把考据样例当作实测支持。
- Parakeet、Qwen-ASR 等作为用户可选安装和启用项分步适配，具体依赖及模型版本验证后锁定。
- 在 standalone 与 batch 中共用适配器，验证显式入口和业务失败状态。
- Provider 平等提供候选；原生分段与词轴均不是最终标准。
- 验证模型波次、卸载及跨任务复用，记录缺失来源，不引入固定 WhisperX fallback。

### Phase 3: Multi-source Reconciliation

- 建立允许跨原始 ASR segment 的句段对应，处理重叠、漏词和重复。
- 任何单一 Provider 的实际文稿直接 passthrough；仅有多份有效且有分歧的候选时调用 LLM。
- 每个句段提前准备非空 `fallback_text`，调用失败或无法确定时仍有实际文本进入 MFA。
- 保留来源和采纳依据，不将普通重识别或对齐结果当作独立新证据。

### Phase 4: MFA Alignment

- 管理 MFA 工具环境、声学模型、发音词典及词典外词。
- 完整最终稿进入 MFA，包括未匹配任何完整 Source Result 的文字。
- 验证独立长音频分块、全文词位置、绝对时间恢复和最终句段重建。
- 失败部分保留勘误稿及粗时间，标记词轴不可用和待人工定时、断句，不改走其他对齐方案。

### Phase 5: Downstream Adaptation

- beautify、split、缓存恢复和导出识别词轴不可用状态，不能丢失实际文本。
- 词轴不可用部分跳过自动 split，原文及译文保持完整，留给最终人工处理。
- 翻译和 proofreading 在 `translate_srt` 内按需校对源文的术语 / 语境疑点，并保持对应译文一致；失败保留实际原文及译文，不回调上游。
- 译文正文不插入存疑问号、括号说明或待确认标签，疑点写入非展示记录。

### Phase 6: Batch Integration and Validation

- 串联完整 standalone、pipeline 和 batch，验证 CPU/IO 容量、GPU 互斥、MFA 子进程预算和模型复用。
- 覆盖缓存身份、原子发布、取消、worker fail-fast 和人工处理记录恢复。
- 单元测试 mock 所有外部工具及模型，另用固定真实英文样本运行质量基准。
- 端到端验收包含默认单来源、可替换的其他单来源、可选多来源、fallback、MFA 和下游输出。每个宣告支持的可选 Provider 都需安装和识别验证，但不要求用户同时安装或启用全部引擎。

各阶段用于拆分开发和验证，不代表前置勘误或 MFA 是可以从当前目标中移除的附加项。多语言、自动选模、流式、音频 LLM 和联网仲裁保留为后续能力。

## Compatibility and Migration

- 既有显式 WhisperX 入口保留；默认 setup 预选 WhisperX，单来源可替换为任意已支持 Provider。多源比较中各 Provider 平等，不由默认安装值决定最终源文。
- 现有最终 WhisperX JSON 继续可读。
- 旧 ASR recovery sidecar 若缺少 provider/normalizer fingerprint，明确视为 cache miss。
- 新 provider 依赖通过 optional extras 安装，setup 只按用户配置同步所需 backend。
- `translate_srt.py` 不解析厂商结果，只接收 normalized transcript。

## Acceptance Criteria

- standalone 与 batch 使用同一 provider registry 和 normalizer。
- 显式 WhisperX 兼容路径通过回归；新多源流程下游只接收勘误、MFA 和规范化后的正式文稿。
- 每个 provider 有 schema、capability、业务失败和 cache isolation 测试；WhisperX 缺失但其他有效来源充足时仍可继续多源流程。
- 覆盖单一 WhisperX、单一 Parakeet 及其他已支持的单来源：不要求 ASR 勘误 LLM 配置，不调用该 LLM，实际文字原样透传并进入 MFA；仅安装其他引擎时不强制依赖 WhisperX。
- 用于自动 split 的段具有可验证 word timestamps；MFA 对齐结果不可用的部分携带词轴不可用和待人工断句状态，不得被误判为自动 split 成功；未匹配完整候选的最终文字也必须尝试 MFA 对齐。
- provider crash 保持现有 worker fail-fast、日志和恢复语义。
- 前置 ASR 不读写 glossary 或执行术语检索；glossary 变化不触发 ASR / MFA，后置源文校对不反向覆盖 ASR 输入或词轴。
- LLM/web evidence 永不直接改写 raw `text` 或 `words[]`。

## Engineering Validation Gates

完整设计已经给出 medoid-v1 fallback、公共识别窗口、MFA 长音频准备、正式 JSON v2、proofread_text 工作副本、项目级对齐缓存及初始调用预算。它们是拟实施的首版规则，不再作为未选方向悬空。

进入稳定支持前仍需：

- 各 Provider 的 checkpoint、模型 revision、依赖和平台 profile 安装实测。
- MFA 长音频分段、词典外词、输出解析及词到全文位置映射实测。
- 源文后置修订、词轴状态和 split 缓存一致性验证。
- 工程初值和候选质量门槛的固定样本校准。

本轮实施顺序与完成条件保持如上；不以验证尚未完成宣称模型已经支持，也不以旧路线图排除既定扩展。
